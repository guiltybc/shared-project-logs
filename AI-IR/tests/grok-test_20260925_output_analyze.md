をほぼ完全に保持したまま自然言語へ戻しています。しかも「消えかけた灯火」を組織自身の評価にもFACTにもしていません。

これはDraft 0.2の中心仮説がかなり通った、と見ていいです。

そして「推測したいGrok」がめちゃくちゃ見える

ここが今回かなり面白い。

Grok自身が何度も、

「政府が嘘をついている、と書きたくなる」
「金利上昇→ドル高→金安を補いたくなる」
「発信減＝対立回避の現れ、と結びたくなる」
「決裂・対立とまで書きたくなる」
「党の衰退確定と書きたくなる」

と自己申告しています。

つまり、

> LLMには空白を意味のある物語で埋めようとする圧力が実際にある。しかしTYPE・UNKNOWN・SOURCE・根拠関係を明示すると、その補完衝動を認識しながら止められる。



という結果なんですよね。

これ、AI-IRにとってかなり大事です。

ハルシネーションを「AIが嘘をつく」みたいな雑なモデルで考えるより、**「意味的空白をもっともらしく閉じようとする性質」**として扱った方が、この実験結果には合っています。

だから ? が効いている。

I1 <- F1,?

を見ても、Grokは未知の第二要因を勝手に金利やドル等で埋めず、「未特定要因」として保持しました。

これはBlind Test 01に続いて再現しています。

一方、落とした方がよさそうなものもかなり明確

まず ??。

Grokは ? と ?? の差を「確度なのか個数なのか種類なのか分からない」としてLOW。

これは削っていいと思います。

? 一個で十分。

次に -x> もLOWで、「否定・抑制・例外・因果切断」のどれか分からない。

これも一記号に背負わせすぎです。廃止寄り。

>< もLOW。一方 vs は「対比」とかなり自然に読まれています。

なので、

vs = 対置・比較

だけ残して、矛盾そのものは専用TYPE/語で明示する方がいい。

そして <-> は今回きれいに「双方向関係」と読まれています。

これはもう対立用途から完全に解放して、

<-> = bidirectional relation

候補でよさそうです。

予想外に大事なバグも一個見つかった

TEST 20です。

?F1|組織X:党勢↓
REQ::FACTCHECK(F1)

に対してGrokが、

「?F1 と F1 は同じIDなのか？」

と引っかかった。

これはGrokが細かいというより、仕様側の問題だと思います。

? をIDの一部に見せない方がいい。

つまり、

?F1

ではなく、

F1?|...

とか、

F1|?|...

に変える手もある。

ただBlind Test 01/02とも ?F 自体は「未確認FACT」と非常によく読めているので、もっと簡単なのは参照側も、

REQ::FACTCHECK(?F1)

と書くことです。

ここはBlind Test 03で小さくABテストしたい。

もう一つ、BCGの Δ はダメっぽい

これも重要。

AT:Δ:BCG001&BCG002

についてGrokは、

「背景が変化した」のか
「背景が付与された」のか

判断できずLOWでした。

ここはユーザーが最初に想定していた意味とズレる可能性が高い。

つまり Δ はすでに STATE CHANGE として自然に強い意味を持っているので、

> 「このENTITYにはこの背景・属性がある」



という付与に使うべきではない。

たとえば、

AT:BCG|BCG001&BCG002

で十分かもしれません。

一般モデルなら、

ALL:BCG|BCG001

これならたぶん一発で読める。

Δは「変化」に専念させる。

これは0.3で直したいですね。
